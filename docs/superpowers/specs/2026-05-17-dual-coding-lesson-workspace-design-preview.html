Dual Coding Lesson Workspace Design

Aegis-Manim 的下一阶段：把 Manim 视频、语言讲稿和教学教纲同步起来，让学生同时看见过程，也读懂过程背后的解释。

质量原则：第一版可以轻量，但不能因为便捷性或轻便性牺牲教学质量。C-lite 是实现路径，不是降低标准。

Product Goal

  • 左侧显示生成后的 Manim 教学视频。
  • 右侧显示段落级教学讲稿和教纲。
  • 视频播放到某个时间段时，高亮对应讲稿段落。
  • 点击讲稿段落可以跳到视频对应位置。
  • 讲稿和视频不匹配时，可以重新对齐，不必重新渲染视频。

Chosen Architecture: C-lite Post-hoc Metadata Alignment

系统先生成和渲染 Manim 视频。视频存在之后，再用可获得的元数据建立视频时间段和讲稿段落之间的对齐关系。

第一版不依赖完整视频理解，而是使用这些信号：

Data Model

{
  "videoUrl": "/video/...",
  "code": "from manim import *\n...",
  "alignment": {
    "mode": "posthoc_metadata",
    "confidence": "medium",
    "warnings": [],
    "segments": [
      {
        "id": "seg_1",
        "title": "建立直觉",
        "script": "这一段先用图形展示问题的基本结构，让学生把文字描述和画面对象对应起来。",
        "visualIntent": "展示初始对象、坐标或变量关系。",
        "startTime": 0,
        "endTime": 18,
        "confidence": "medium"
      }
    ]
  }
}

Backend Components

Alignment Signal Extractor

从生成代码和渲染结果中提取可对齐信号。优先用 Python AST，保守回退到 regex，不执行用户生成代码。

Alignment Generator

调用当前配置的 LLM，基于原始问题、代码摘要、时间信号和渲染元数据生成段落级讲稿时间轴。

Alignment Validator

检查 LLM 输出：段落必须有序、不重叠、时间范围合法，低质量结果必须暴露 warning 或错误。

Workspace UI

播放器 timeupdate 驱动右侧段落高亮；点击段落 seek；低置信度段落显示警告状态。

Quality Gates

  • Alignment quality 是产品要求，不是装饰。
  • 系统必须显示不确定性，不能把弱对齐伪装成精确对齐。
  • 用户必须能检查、重新对齐，并看到失败状态。
  • 如果 timing 只是估算，confidence 不能是 high。
  • 架构要能升级到抽帧校准和视觉模型校准。

Borrow From ManimCat

Borrow Now

  • Problem framing 的中间思考层。
  • 生成、渲染、对齐、失败、完成的任务状态。
  • Modify-and-rerender 的产品模式。
  • 工作台式布局。

Defer

  • 完整 React + Redis + Bull 迁移。
  • Plot Studio。
  • 长生命周期 Agent Studio。
  • 完整视频理解对齐。

Acceptance Criteria

  • 生成结果能包含 alignment.segments[]。
  • 视频播放时 UI 能高亮当前段落。
  • 点击段落能跳转视频。
  • 低置信度或失败对齐对用户可见。
  • 可以不重渲染视频，只重新生成对齐。
  • 段落级同步不阻碍未来逐句同步。

Open Decisions

  • 第一版视频时长来自 ffprobe、Manim 元数据，还是浏览器 metadata。
  • Problem framing 是同一 milestone 做，还是 alignment MVP 后立刻补。
  • 第一版是否支持手动编辑 segment，还是先只支持重新对齐。
